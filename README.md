# EKO Manager

Вътрешно Django приложение за управление на клиенти, горивни карти, исторически цени и транзакции, както и за генериране на Excel/PDF отчети за фактуриране.

## Основна логика

- Картата свързва транзакцията с конкретна фирма.
- За всяка транзакция се използва последната ценова листа със същия продукт и дата, която е по-ранна или равна на датата на транзакцията.
- При марж: `GTA цена = базова ЕКО цена + марж`.
- При отстъпка: `GTA цена = цена от транзакцията - отстъпка`, но не по-малко от нула.
- Без марж/отстъпка се използва договорната крайна цена, а при липса на ценова листа — цената от транзакцията.
- GTA цената се отрязва до третия знак без закръгляне.
- За `Е GАS LРG` печалбата е `(0.015 € − отстъпка на литър) × литри`.
- Фирмите с двукратно фактуриране автоматично използват период 01–15 или 16–края на месеца според последната дата във файла.
- Excel обобщението показва средна претеглена GTA цена с пет знака.

## Стартиране под Windows

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Отворете `http://127.0.0.1:8000/`.

## Настройки

За локална работа стойностите по подразбиране са достатъчни. Преди публикуване задайте променливите от `.env.example`, особено `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=false`, `DJANGO_ALLOWED_HOSTS` и `DJANGO_CSRF_TRUSTED_ORIGINS`.

## Работен процес

1. Импортирайте `cards.xlsx`.
2. Импортирайте един или повече файлове с ценови листи.
3. Импортирайте файла с транзакции. Той заменя транзакциите от предишния отчетен период.
4. Проверете несвързаните записи на началното табло.
5. Отворете фирма и изтеглете Excel, PDF или ZIP отчет.

## Проверка

```powershell
python manage.py check
python manage.py test
```

Приложението използва SQLite. Моделите и бизнес слоят са отделени така, че по-късно базата да може да бъде сменена с PostgreSQL/Supabase без промяна на правилата за изчисление.
